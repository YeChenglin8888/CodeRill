# CodeRill：面向 AI Agent／AI 应用开发岗位的实践路线

规划日期：2026-10-18。时间假设：6 周，每周约 12–15 小时；按验收结果推进，周数是安排参考。目标是完成可演示、可复现、能解释设计取舍的个人项目。

## 1. 项目定位与完成标准

项目名称建议：**CodeRill：支持工具执行、任务恢复与桌面交付的编程智能体**。

面试时用一句话介绍：用户通过客户端提交代码任务，Agent 读取项目、调用工具、提出修改并请求审批；系统记录执行过程，支持恢复任务，并提供安装包和容器两种交付方式。

最终要交出：

1. 一段 3–5 分钟演示：提交任务 → 工具执行 → 修改审批 → 验证结果 → 重启恢复。
2. 架构图和关键设计说明：模型、运行时、工具、审批、会话、前端之间如何配合。
3. 一份真实任务评测报告，附固定任务集、模型配置、版本、原始结果和失败分析。
4. Windows 安装包、带版本的 Docker 镜像和部署说明。
5. 一次成功和一次被测试阻断的 Jenkins 构建记录，以及一次部署回滚记录。
6. 三条可以指向源码和证据的简历描述。

## 3. 六周执行顺序

### 第 1 周：讲清运行链路，形成可复现演示

学习：Function Calling、Agent 循环与退出条件、异步执行、事件记录、审批和恢复。

行动：

- 从一次用户输入跟踪到模型请求、工具调用、结果回填和最终答复，记录对应入口。
- 运行已有离线失败演示，复现审批期间文件变化、工具执行中断和会话恢复。
- 画一张架构图，写出选择自研运行时的原因，以及未来什么情况下值得引入 LangGraph。
- 记录当前提交或源码快照、依赖和测试结果，作为后续对照基线。

验收：不看源码能讲清 5 分钟执行链路；能展示“发生了什么、日志记录了什么、恢复后能确认什么”。遇到结果未知的外部副作用，要能解释为何不能直接重试。

证据：架构图、演示录像、关键源码索引、测试输出。

### 第 2 周：建立真实任务评测，做一次有依据的改进

学习：任务成功率与单元测试通过率的区别、验证器、模型随机性、上下文预算、耗时与 token 统计。

行动：

- 复用 `examples/benchmark_suite.py`，设计 12 个小任务，覆盖定位问题、修改代码、执行测试和多步操作。每个任务有固定初始代码和明确验证器。
- 先跑少量任务校验评测流程，再在确定模型调用预算后执行完整任务集。建议每题运行 3 次，共 36 次；这是实验规模计划，不是现有效果数据。
- 固定模型、任务版本、工具权限和预算，记录完成结果、耗时、调用轮数；记录模型返回的实际 usage，缺失值标为缺失。费用按对应模型价格单独估算。
- 根据失败记录只选一个改进点，例如上下文压缩后的信息恢复或错误反馈。使用相同任务和模型做改进前后对照。
- 若使用评测任务调参，另留未参与调参的任务检查效果，防止只适配已知题目。

验收：每个“成功”都有验证器支持；基础设施错误单独报告；对照结果包含样本量、重复次数、配置与失败案例。少量任务结果只支持项目内结论。

证据：任务清单、原始 JSON、汇总表、失败案例、改进提交。

### 第 3 周：将精细客户端接入真实 Agent

学习：TS 状态管理、流式响应、前后端协议、取消语义和错误展示。

行动：

- 以现有 TS 客户端和设计原型为基础，统一侧边栏、对话区、输入框、模型菜单和工具卡片。
- 建立 CLI → 客户端能力清单，逐项记录入口、接口、状态和验证结果。优先完成会话、模型配置、工具进度、审批、取消、恢复；其余已有能力逐项补齐。
- 为后台任务、子任务、工作区修改和计划提供入口；明确依赖宿主机程序的能力，防止按钮存在但无法执行。
- 覆盖运行中、等待审批、失败、取消中、已停止、连接中断、恢复后的状态；确认界面显示与后端事实一致。

验收：同一个隔离示例项目，通过 CLI 和客户端完成同一任务；全部已列出的 CLI 能力都有可用入口或明确的环境限制说明。完成键盘操作和常用窗口尺寸检查。

证据：能力映射表、交互录像、关键集成检查结果。

### 第 4 周：完成容器交付和回滚演练

学习：镜像与容器、多阶段构建、端口映射、数据卷、环境变量、健康检查、版本和回滚。

行动：

- 复习已有 Dockerfile 和 Compose，逐条解释每个配置的作用。
- 以提交号或发布版本标记镜像，记录镜像摘要；选定镜像仓库后完成推送与拉取。
- 在独立 Linux 虚拟机或测试主机上部署，验证接口、目录挂载和会话持久化。服务器未准备好时先做本机演练，并准确记录范围。
- 部署 v1 → 更新 v2 → 回滚 v1，检查会话与工作目录；记录配置、备份与恢复步骤。涉及数据格式变化时先验证兼容性。

验收：目标环境通过拉取镜像和配置启动服务；替换容器后会话仍可恢复；回滚记录包含镜像版本、操作和验证结果。

证据：镜像摘要、部署日志、存储验证和回滚记录。当前服务缺少面向公网的登录保护，测试环境保持本机或受限网络访问。

### 第 5 周：让 Jenkins 真正完成一次 CI/CD 流程

学习：Controller 与 Agent、Pipeline、凭据管理、制品、质量门禁和部署权限。

行动：

- 复用 `docs/examples/Jenkinsfile.windows`，搭建 Jenkins 和构建节点，连接授权的代码仓库。
- 先运行现有测试、前端构建和镜像构建；按本次改动范围补齐必要检查，记录输出。
- 测试通过后发布带版本的镜像；部署到测试环境后执行健康和持久化检查，部署初期保留人工触发。
- 故意提交一个会失败的测试，验证流水线停止、后续发布与部署没有执行；随后修复并验证通过。
- 密钥放 Jenkins 凭据，确认代码和构建日志不包含密钥。

验收：有成功构建、失败阻断、测试环境部署三个可追溯记录；每次能追踪源码版本、镜像版本和验证结果。

证据：实际运行的 Jenkinsfile、构建日志、失败门禁截图、部署记录。只启动 Jenkins 或保存模板，不能记作完成 CI/CD。

### 第 6 周：生成 Windows 安装包，整理面试材料

学习：Python 冻结打包、静态资源路径、桌面壳和后端进程生命周期、安装与用户数据目录。

行动：

- 按教程先打包最小 Python 示例，再为 CodeRill 增加明确的后端打包入口。
- 采用既定 Tauri + Python sidecar 方案连接 TS 界面和后端。处理端口占用、启动就绪、退出清理和错误日志。
- 区分程序安装目录、用户配置、会话目录和项目工作目录；检查依赖外部程序的工具如何提示和安装。
- 生成安装包，在未安装开发用 Python／Node 的 Windows 用户环境中，验证安装、启动、真实任务、退出、再次启动和卸载。Tauri 系统运行时与外部工具依赖应写入说明。
- 整理三分钟项目介绍、三个技术难点、两个失败案例和全部证据链接。

验收：交付可安装文件和实际验证记录；用户配置与会话不会因普通升级被覆盖。若尚未验证升级行为，明确标为未验证。

证据：安装包与校验值、安装录像、验证清单、简历描述。

## 4. 每周持续准备的基础知识

每周从时间预算中留出约 3 小时，结合项目练习：

- Python：asyncio、超时取消、异常、进程与线程、文件操作。
- 后端：HTTP、流式传输、断线恢复、鉴权、幂等与重试、日志定位。
- Agent：工具 schema、结构化输出、上下文压缩、记忆与 RAG 的区别、MCP、子任务预算。
- 算法与工程：常见数据结构题、Git、Linux 排查、测试设计。

针对框架知识，可以解释当前循环如何映射到图节点、状态、条件边和检查点。只有目标岗位明确要求且现有项目需要时，再增加小范围 LangGraph 对照实验。

## 5. 简历怎么写

### 当前已有证据可支撑的描述

> 为 CodeRill 编程智能体实现 Docker 多阶段构建与 Compose 单机部署，配置项目目录挂载、会话数据卷及健康检查，并验证容器替换后的会话持久化恢复。

使用前需亲自复现并能解释相关配置；代码由 AI 协助完成的部分也应能独立排查。

### 后续完成验收后使用的三条描述

1. 围绕编程任务构建 Agent 执行链路，支持工具调用、写操作审批、事件记录和会话恢复；通过中断与过期审批场景验证恢复行为及副作用边界。
2. 建立带独立验证器的任务评测集，固定模型、权限与预算开展重复实验，记录任务完成率、耗时和 token 消耗，依据失败分析优化【实际改进点】，在【任务与样本规模】上获得【实测结果】。
3. 将 TS 客户端接入共享 Agent 运行时，提供流式对话、工具进度和审批交互；通过 Docker 和 Jenkins 实现测试、镜像构建及测试环境交付，并完成 Windows 安装包验证。

方括号内容必须等实测后填写；部分能力未完成时删除对应分句。简历最终保留最强的三条，详细过程放项目 README。

## 6. 面试自检

每个问题都要给出代码位置或演示证据：

1. 一次任务如何结束？工具持续失败时怎样停止？
2. 为什么自研编排？引入 LangGraph 会获得什么、付出什么？
3. 审批后文件被外部修改，如何防止使用过期 diff？
4. 工具执行中进程退出，如何判断已执行、未执行和未知？
5. 压缩上下文后丢失关键信息，如何恢复与评估？
6. 子 Agent 如何限制预算、隔离修改并合回结果？
7. 成功率的分母是什么？失败如何分类？优化有没有模型随机性的影响？
8. 流式连接断开后，如何区分任务继续运行和任务停止？
9. 容器删除后什么数据还在？健康检查失败是否会自动重启？
10. Jenkins 在哪里执行构建？测试失败如何阻止发布？怎样回滚？
11. 安装包包含什么？哪些系统依赖和外部工具仍需要安装？
