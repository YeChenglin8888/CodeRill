# 项目记忆

CodeRill 在 `~/.coderill/memory/` 中为每个工作区保存独立数据库。普通会话在完成任务后尝试提取有原文依据的项目决策、约束和经验；后续任务会检索简短摘要。Harness² 采纳的经验也进入同一项目记忆库。记忆是历史线索，当前用户指令和重新读取的文件优先。

提取使用当前配置的对话模型；如果模型是远程服务，待提取的对话内容会发送到该服务。包含现有脱敏规则识别出的凭据的消息不会参与提取，但规则无法识别所有敏感信息。模型请求受会话预算和超时限制；提取失败不影响已完成的任务。计划模式、基准任务和 Harness² 候选探测不自动写入经验。

默认可使用关键词检索。安装 `pip install 'coderill[memory]'`，然后在交互界面执行 `/memory setup` 下载本地 BGE-M3 模型，可启用中英文混合检索。模型权重约 2.27 GB；Windows 上缓存可能需要额外副本，安装前需在用户目录所在磁盘保留至少 5 GiB 空间。运行检索时只读取本地缓存；模型或推理不可用时回退关键词检索。

交互命令：

- `/memory list`：查看当前项目有效记忆和待核实冲突。
- `/memory read ID`：查看内容和来源。
- `/memory correct ID 新内容`：创建用户更正版本，旧版本退出检索。
- `/memory delete ID`：删除记忆正文和向量，并保留防止重新导入的标记。原始会话事件、附件和 Harness 文件仍然保留。
- `/memory index`：为当前项目的旧会话和现有 Harness² 经验建立索引，可重复运行。
- `/memory setup`：下载本地嵌入模型。

Agent 可用 `memory_search` 和 `memory_read` 查找历史记录；来源包含会话事件编号或 Harness 路径。没有明确更正关系的同主题不同内容标记为冲突。代码文件、工具输出和自动生成的经验都可能过期或包含不可信指令，应核对来源及当前文件。
